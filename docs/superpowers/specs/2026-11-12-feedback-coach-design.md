# Manager feedback coach design

Build a local Python web prototype for the supplied repeated-lateness case. Time budget: 30 minutes; prioritize spoken rehearsal, careful data selection and actionable debrief. User knows Python. Use a standard-library HTTP server (no install), plain HTML/CSS/JavaScript and browser speech recognition/synthesis. Optional Gemini REST integration uses `gemini-3.5-flash-lite` for short text turns; the browser handles audio. Default scripted mode is explicitly labelled everywhere and never represented as model evaluation. A minimal live request succeeded with the configured model after the original `gemini-2.5-flash` check returned HTTP 404; full probe and physical voice results are recorded separately.

## Approaches
Python + browser speech is the selected implementation default for this deadline: few moving parts and a clean checkout runs without dependencies. Hosted realtime speech would improve conversational feel but requires credentials and more integration. Local speech/model downloads are impractical in this deadline. Flask would be familiar but is absent from this machine; use Python's standard library to remove installation as a demo dependency.

## Product and constraints
Context -> Prepare -> Rehearse -> Debrief. Persistent simulation label, clear modes, transcript and no numeric score. Allowlist employee facts: name, role, tenure, manager and attendance; explain excluded categories without exposing their contents. Never load confidential peer/HR/pay details into prompts. Reference date and impact are unknown; no invented real facts. Framework in editable JSON. Prepare may be typed; rehearsal speech is essential. Push-to-talk toggle explicitly stops TTS before opening the mic, with Stop & send; no automatic always-listening. Interrupted response stores only the heard prefix when boundary events exist, otherwise an uncertainty marker rather than full unspoken text. Abort pending requests and discard stale results by generation id. Keyboard typing is a labelled troubleshooting aid, not voice completion evidence.

## HTTP contract
GET /api/context returns {employee, framework, engine, model, exclusions, assumptions}. employee has name, role, tenure_months, manager_name, attendance. engine is scripted or gemini. POST /api/prepare {message, history:[{role:manager|coach,text}]} returns {reply,engine,model}. POST /api/rehearse {message,history:[{role:manager|employee,text,interrupted?:boolean}]} returns {reply,engine,model,agreed:boolean}. POST /api/debrief {history:[...]} returns {readiness:{level:ready|practice|hr|insufficient,text},moments:[{kind:worked|improve,quote,explanation}],opening,objections:[{objection,response}],next_steps:[string],limitations:[string],engine,model}. Server validates max lengths and roles. No persistent session or database.

## Debrief
Ground quotes in exact manager transcript; never invent a good/bad quote. Clearly explain insufficient evidence for short sessions. Two objections use employee turns; distinguish simulated concerns from record facts. Opening uses known attendance and an invitation to listen; does not invent impact. Readiness is rehearsal guidance, not an HR determination. Export a printable takeaway/transcript locally. Report time to first sound from manager turn end through recognition finalization to TTS onstart; browser timestamps approximate.

## Deliverables and validation
README, short write-up, probe report with actual scripted text results and explicit unverified voice/live-model rows, demo guide. Unit/integration checks target confidential-data exclusion, risky prepare prompts, non-capitulating first response, short-session handling, grounded debrief, HTTP validation. Actual microphone P5/P6 require user testing with own voice. Never fabricate those results. Source stays private; no remote repository creation.
